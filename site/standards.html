Standards

Recognized standards, applied on every change.

CoFlow ships rule sets mapped to the public standards auditors and customers ask about. You switch them on, edit them, and add your own. Each one is enforced where it does the most good.

CoFlow rule sets are written by CoFlow and mapped to each standard's identifiers. They do not reproduce licensed standards text, and using them is not a certification of compliance.

Enforcement

Four places a standard takes effect.

01In contextThe rules that apply to the task are in front of the agent before it writes.
02On the planThe agent's plan is checked against those rules before any code exists.
03On the pull requestA required check flags violations and links the rule.
04On commandsRisky commands are blocked or need confirmation, and every decision is logged.
Rules from what you already have

Your team has already written its standards. They are just not in one place.

01Your existing codebaseCoFlow scans the repository for the conventions it already follows, such as naming, error handling, test layout and folder structure, and drafts them as rules.
02Pull request and merge request reviewsPast and new review comments show what your team corrects. Repeated corrections become proposed rules with the comments linked.
03Jira and LinearBugs, incidents and decisions carry the reasons behind a rule. CoFlow links each rule to the tickets that justify it.

Every proposal goes to a person. Approve or reject it in a pull request, or from Slack or Microsoft Teams.
