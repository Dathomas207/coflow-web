See it work

An agent's first interrupt handler, and the one you would have written.

RequestLog each line received on the UART.

Agent aloneuart_isr.c
void USART1_IRQHandler(void) {    char *line = malloc(128);    read_line(line, 128);    printf("rx: %s\n", line);    free(line);}
  • MISRA C 21.3Heap allocation with malloc and free.
  • MISRA C 21.6Standard input and output called from firmware.
  • Team ruleA blocking read inside an interrupt handler.
With CoFlowuart_isr.c
void USART1_IRQHandler(void) {    rx_ring_push(USART1->DR);    rx_pending = true;} /* main loop drains rx_ring and logs */
  • MISRA C 21.3A fixed ring buffer, allocated at startup.
  • MISRA C 21.6Logging moved to the project logger in the main loop.
  • Team ruleThe handler stores one byte, sets a flag and returns.
Where the team rule came fromA failed hardware-in-the-loop run, approved by your team as a rule.

Illustrative example. Rule identifiers refer to MISRA C:2012.

Firmware starter standards

The rules every hardware engineer learns the hard way.

01Interrupts stay shortNo blocking calls, allocation or printing inside an interrupt handler. Set a flag and return.
02No heap after startupAllocate at init. After that, fixed buffers and pools only.
03Registers go through the HALNo raw addresses in application code.
04The pin map is the source of truthPins are named once, in one file, and never by number elsewhere.
05Units live in the nametimeout_ms, not timeout. current_ma, not current.
06Every watchdog has an ownerOne task feeds it, and the reason is written down.
ABench failures become rulesA failed hardware-in-the-loop run or a logged brown-out is evidence. CoFlow drafts the rule and your team approves it.
BDeviations on the recordWhen a rule has to be broken, the rule, the reason and the approver are logged.
COne standard for firmware and appThe same review flow covers the board, the back end and the screen.
