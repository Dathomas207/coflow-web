Use case: front end

Screens that look like your product.

Agents write a working form in seconds, and it rarely matches your design system or passes an accessibility audit. CoFlow pulls in your tokens and components and holds every screen to WCAG 2.2.

The same request, with and without your standards.

RequestAdd an email field and a submit button to the sign-up form.

Agent aloneSignupForm.tsx
export function SignupForm() {  return (    <form onSubmit={submit}>      <input placeholder="Email" onChange={setEmail} />      <div className="btn" style={{ background: "#2f6fed" }}        onClick={submit}>Sign up</div>    </form>  );}
  • WCAG 3.3.2A placeholder in place of a label.
  • WCAG 2.1.1A clickable div that a keyboard cannot reach.
  • Color tokensA hard-coded hex value close to the brand blue.
With CoFlowSignupForm.tsx
import { Field, Button } from "@/ui"; export function SignupForm() {  return (    <form onSubmit={submit}>      <Field label="Work email" type="email" onChange={setEmail} />      <Button type="submit" variant="primary">Sign up</Button>    </form>  );}
  • WCAG 3.3.2The shared Field renders a visible label.
  • WCAG 2.1.1A real button, reachable and operable by keyboard.
  • Color tokensColor comes from the primary variant.
Where the rules came fromYour design system, pulled in as tokens and components, plus WCAG 2.2 AA mappings.

Starter standards

The rules your designers keep writing in review.

01Use the shared componentsButtons, fields and dialogs come from the design system, never rebuilt.
02Colors come from tokensNo hex values in components. Contrast is checked on the token pair.
03Spacing comes from the scaleNo one-off pixel values for padding, gaps or radius.
04Every input has a labelVisible labels, with errors announced to assistive technology.
05Everything works by keyboardFocus is visible and follows the reading order.
06Copy follows the style guideButton text says what happens. Errors say how to fix them.
