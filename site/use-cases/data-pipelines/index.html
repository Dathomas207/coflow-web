Use case: data pipelines

Pipelines you can rerun at 3am.

A data job that works once is easy. One that can be rerun, rejects bad input and never copies personal data into the warehouse takes rules. CoFlow gives every agent the rules your data team learned the hard way.

See it work

The same request, with and without your standards.

RequestLoad the daily events file into the warehouse.

Agent aloneload_events.py
def load_daily(day):    df = pd.read_csv(f"s3://raw/events/{day}.csv")    df.to_sql("events", engine, if_exists="append")
  • Team ruleA rerun of the same day duplicates every row.
  • Team ruleBad input is loaded without a check.
  • Privacy ruleEmail addresses land in the warehouse in plain text.
With CoFlowload_events.py
def load_daily(day):    df = pd.read_csv(f"s3://raw/events/{day}.csv")    df = EventSchema.validate(df)    df["email"] = hash_pii(df["email"])    with engine.begin() as tx:        tx.execute(delete(events).where(events.c.day == day))        df.to_sql("events", tx, if_exists="append", index=False)
  • Team ruleThe day is replaced in one transaction, so reruns are safe.
  • Team ruleThe declared schema rejects bad input before it loads.
  • Privacy rulePersonal fields are hashed before they leave the raw zone.
Where the rules came fromTwo incident tickets about duplicated rows and one review comment from your data lead.

Starter standards

The rules behind a pipeline nobody has to babysit.

01Every job is idempotentRunning the same day twice gives the same result as running it once.
02Schemas are declaredInput is validated against a schema before it is loaded.
03Personal data stays in the raw zonePersonal fields are hashed or dropped before they reach shared tables.
04Loads are transactionalA failed load leaves the target table as it was.
05Backfills run in batchesLarge backfills run in bounded chunks with progress logged.
06Credentials come from the vaultNo connection strings in code or notebooks.
