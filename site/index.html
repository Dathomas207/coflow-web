Agent aloneuart_isr.c

  • MISRA C 21.3Heap allocation with malloc and free.
  • MISRA C 21.6Standard input and output called from firmware.
  • Team ruleA blocking read inside an interrupt handler.
With CoFlowuart_isr.c
void USART1_IRQHandler(void) {    rx_ring_push(USART1->DR);    rx_pending = true;} /* main loop drains rx_ring and logs */
  • MISRA C 21.3A fixed ring buffer, allocated at startup.
  • MISRA C 21.6Logging moved to the project logger in the main loop.
  • Team ruleThe handler stores one byte, sets a flag and returns.
Where the team rule came fromA failed hardware-in-the-loop run, approved by your team as a rule.

How it works

From a review comment to a rule every agent follows.

    Connect one repository

    Install on GitHub, GitLab or Bitbucket. There is no pipeline to migrate.

  2. 2

    CoFlow reads the evidence

    Existing code, review comments, failed checks and tickets are where your corrections already live.

  3. 3

    It proposes a rule

    Each proposal has a scope and links to the comments and runs it came from.

    Merge to approve, close to reject. Approved rules reach every agent you use.

Before and after

What changes when the standards are in the loop.

Without CoFlow

  • Each agent relearns your conventions in every session.
  • The same review comment gets written again next week.
  • Standards sit in a wiki that no agent loads.
  • Nobody can say whether a rule is being followed.

With CoFlow

  • Every agent starts with the rules that apply to the task.
  • A correction made once becomes a rule your team approved.
  • Standards are checked on the plan and on the pull request.
  • A scorecard shows adherence for every merged change.

A fair question

"We already keep a rules file in the repo."

That works until the team has more than one agent. Three things go wrong first.

01The whole file loads every timeCost grows and the relevant line gets buried. CoFlow scopes each rule by path and technology, so a migration rule stays out of a CSS change.
02Nobody reviews itThe agent that made the mistake writes the rule, and rules start to contradict each other. CoFlow puts every rule through a pull request.
03Only one tool reads itA teammate on a different agent never sees it. CoFlow writes each approved rule out for every agent.

Questions

What teams ask first.

Something else on your mind? Talk to us.

Does CoFlow replace our coding agents?

No. CoFlow works with Claude Code, Codex, Cursor and Copilot. It gives the agents you already chose the same reviewed set of rules.

Where do the rules live?

As plain files in your repository, versioned and reviewed like code. If you stop using CoFlow, you keep every rule.

Who decides what becomes a rule?

Your team. CoFlow drafts proposals from your code, reviews and tickets, and every proposal goes to a person. Approve or reject it in a pull request, or from Slack or Microsoft Teams.

Does switching on a rule set make us compliant?

No. CoFlow rule sets are mapped to each standard's identifiers. They do not reproduce licensed standards text, and using them is not a certification of compliance.

Does it work for firmware?

Yes. The same product runs on embedded C, with MISRA C and CERT C mappings and bench failures as evidence. Read the firmware application.
