The same request, with and without your standards.

Four changes an agent wrote alone, and the same four with CoFlow in the loop. Each finding names the rule it comes from.

RequestLog each line received on the UART.

Agent aloneuart_isr.c
void USART1_IRQHandler(void) {    char *line = malloc(128);    read_line(line, 128);    printf("rx: %s\n", line);    free(line);}
  • MISRA C 21.3Heap allocation with malloc and free.
  • MISRA C 21.6Standard input and output called from firmware.
  • Team ruleA blocking read inside an interrupt handler.
With CoFlowuart_isr.c
void USART1_IRQHandler(void) {    rx_ring_push(USART1->DR);    rx_pending = true;} /* main loop drains rx_ring and logs */
  • MISRA C 21.3A fixed ring buffer, allocated at startup.
  • MISRA C 21.6Logging moved to the project logger in the main loop.
  • Team ruleThe handler stores one byte, sets a flag and returns.
Where the team rule came fromA failed hardware-in-the-loop run, approved by your team as a rule.

RequestAdd an endpoint that returns one invoice.

Agent aloneinvoices.py
@router.get("/invoices/{invoice_id}")def get_invoice(invoice_id: str, db=Depends(get_db)):    q = f"SELECT * FROM invoices WHERE id = '{invoice_id}'"    return db.execute(text(q)).first()
  • CWE-89The query is built from user input.
  • OWASP Top 10 A01Any caller can read any tenant's invoice.
  • FastAPI standardNo response model, so every column is returned.
With CoFlowinvoices.py
@router.get("/invoices/{invoice_id}", response_model=InvoiceOut)def get_invoice(    invoice_id: UUID,    user=Depends(current_user),    db=Depends(get_db),):    invoice = invoices.get_for_tenant(db, user.tenant_id, invoice_id)    if invoice is None:        raise HTTPException(status_code=404)    return invoice
  • CWE-89A typed id and a parameterized repository call.
  • OWASP Top 10 A01The lookup is scoped to the caller's tenant.
  • FastAPI standardThe response model lists the fields that leave the API.
Where the rules came fromPublic security standards, plus the practices keyed to the framework this repository uses.

RequestAdd a pay button to the checkout page.

Agent aloneCheckoutButton.tsx
export function PayButton() {  return (    <button style={{ background: "#2f6fed",      padding: "11px 18px", borderRadius: 7 }}>      Pay now    </button>  );}
  • Color tokensA hard-coded hex value that is close to the brand blue.
  • Spacing scalePadding and radius that match nothing else in the app.
  • Shared componentsA native button with no focus or disabled states.
With CoFlowCheckoutButton.tsx
import { Button } from "@/ui/button"; export function PayButton() {  return (    <Button variant="primary" size="md">      Pay now    </Button>  );}
  • Color tokensColor comes from the primary variant.
  • Spacing scaleSize comes from the scale.
  • Shared componentsFocus, hover and disabled states come with the component.
Where the rules came fromYour design system, pulled in as tokens and components.

RequestAdd a region column to orders and backfill it.

Agent alone0042_order_region.py
def upgrade():    op.add_column("orders", sa.Column("region", sa.Text()))    op.execute("UPDATE orders SET region = 'us'")
  • Team ruleThe backfill runs with no tenant context, so it sees no rows and passes.
  • Team ruleOne statement updates the whole table in a single lock.
With CoFlow0042_order_region.py
def upgrade():    op.add_column("orders", sa.Column("region", sa.Text()))    for tenant in all_tenants():        with tenant_context(tenant):            backfill_in_batches("orders", region="us")
  • Team ruleEach tenant is backfilled with its context set.
  • Team ruleRows are updated in batches.
Where the rules came fromTwo review comments and one incident ticket in your own history.
