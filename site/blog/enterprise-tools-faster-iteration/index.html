Bring more tools in house. Keep the engineering standard.

AI lets business teams build the internal tools they need. A short production baseline and reviewed rules keep each new tool owned, secure and maintainable.

By CoFlow · November 20, 2026 · 3 min read

On this pageGeneration got faster than reviewAgree on a production baselineSplit the work by who knows whatStart with one bounded tool

An operations team needs a reconciliation tool. Support wants a queue that matches how it triages. Finance wants an approval flow that follows its real sign-off rules. With AI coding agents, the people who understand the problem can now build a working version in days instead of waiting a quarter for engineering time.

That is a real gain, and it comes with more software to own. Every tool that ships needs someone who answers for its data, its access and what happens when it breaks.

Generation got faster than review

DORA analyzed 1,110 open-ended survey responses from Google engineers, collected in the third quarter of 2025, in Balancing AI tensions. Engineers reported that AI speeds up initial code generation and makes new tasks easier to start. They also reported that much of the time saved gets spent again on careful review and verification of what the AI produced.

When more people produce more code, review capacity becomes the constraint. The fix is to settle the recurring questions once, so reviewers spend their time on what is new in each change.

Agree on a production baseline

Before the first internal tool ships, agree on a short list that every tool meets. Keep it small enough that a business team can meet it without an engineer pairing on every change:

RequirementWhy it mattersHow to check it
Company sign-inNo local passwords to leak or forget to revoke.Sign-in goes through your identity provider; removing a user there removes access.
Tenant- or team-scoped dataA shared tool must not show one team another team’s records.Denied-access tests run in CI with the app’s real database role.
No secrets in code or logsGenerated code often hard-codes keys and logs whole requests.Secret scanning in CI; log output reviewed for tokens and personal data.
Reviewed migrationsHand-edited schemas drift between environments.Migrations live in the repository and run the same way everywhere.
A named ownerSomeone has to answer the page when it breaks.Owner recorded in the repository and the service catalog.

Each row can become a reviewed CoFlow rule scoped to the internal-tools repositories. The rules registry keeps the approved revision, and acceptance checks state what has to pass. The agent writing the next tool starts with the baseline instead of rediscovering it in review.

Split the work by who knows what

Take an internal approvals app. The finance team defines the workflow, the approval limits and the failure cases, because they know them. Engineering reviews the access model, the shared components and the deployment. The coding agent gets the approved rules for the change, and a reviewer checks the implementation and the test results before release.

Engineering stays in the loop without writing every line. Its judgment lives in the rules every tool starts with.

Start with one bounded tool

Choose a workflow with a clear owner and a small data boundary, such as a single team’s queue rather than a company-wide system of record. Track time from request to accepted change, review rounds, recurring baseline violations and defects found after release.

If the second tool ships faster than the first with fewer baseline findings in review, the rules are working. Then open the baseline to the next team.
