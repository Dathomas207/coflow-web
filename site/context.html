Project memory

Learned once. Never asked again.

Every new agent session starts by rediscovering where the database is, how to read the logs and which service owns what. CoFlow keeps those facts in your repository, so an agent learns them once and every later session starts with them.

The system map

A map of how your system fits together.

CoFlow detects what it can from your files, and agents and people fill in the rest.

Three layers of trust

Every answer says where it came from.

1VerifiedFacts a person declared or accepted, kept in system.yaml and changed only through a pull request.
2LearnedFacts an agent stored with remember. Marked unverified until a person accepts them. A fact learned twice gains a confirmation; one that contradicts an earlier fact is kept beside it and flagged.
3DetectedWhat CoFlow can read from your files on each request. Computed fresh, never stored.

No file stores a credential. A fact can only name where a secret lives.

Facts and rules

Facts are remembered. Rules are approved.

A rule changes how agents work, so it takes effect only after a person approves it. A fact about the project is useful the moment an agent learns it, so it is stored right away and reviewed later. Promote turns a batch of learned facts into one proposal; accept moves them into the verified map.

ToolWhat it does
rememberStore a fact an agent just learned
correct, forgetFix or drop a fact
staleList facts that may be out of date
promote, acceptReview learned facts and make them verified
setupDetect the system, install playbooks and leave five questions for a person to answer once
Playbooks

When to reach for another system, and how.

Playbooks tell an agent when the logs, the cloud console or the tracker will answer a question faster than the code, and how to use them in your setup. CoFlow installs the ones whose systems you actually run.
