Documentation / Get started

Your first useful instruction package

Start with one repository, one engineering lesson and one task.

Get access

Request pilot access and have your administrator confirm your organization, project, role and application URL. Use the sign-in method configured for your workspace. A successful identity-provider login alone does not grant local project membership.

Capture and review a rule

Choose a recurring problem, such as tenant-scoped invoice queries. Record the intended behavior, affected paths, exceptions, supporting evidence and acceptance checks. Submit the proposal, then have an authorized reviewer approve it. With single sign-on turned on, someone other than the author must approve it.

Compile the next task

Supply the task, repository, files and technologies. The compiler selects applicable approved guidance and returns a persisted package. This example is a request body for POST /v1/instructions/compile on your provisioned API:

{
  "project": "your-project",
  "task": "Add a tenant-scoped invoice lookup",
  "repository": "your-team/your-repo",
  "files": [
    "app/invoices/routes.py"
  ],
  "technologies": [
    "postgresql",
    "fastapi"
  ],
  "budget_tokens": 2000
}

Use your assigned project and the technology labels attached to your rules. Check the response status and selection reasons. Resolve a blocked package before continuing.

Record what happened

Keep the package ID, run your required checks in your development environment, and record the observed outcome with evidence. A missing result is awaiting feedback, not a success. Compare with a similar baseline task when evaluating efficiency.
