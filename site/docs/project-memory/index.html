Project memory: facts learned once

Facts about your system that an agent looks up once, so no later session has to find them again.

Three layers

  • Declared: .coflow/context/system.yaml, verified entries changed through a pull request.
  • Learned: .coflow/context/learned.yaml, facts agents stored with remember, marked unverified and capped at 300.
  • Detected: computed from your files on each read and never stored.

Reads merge the layers in that order of trust, and every answer names the layer it came from.

The system map

The system map describes services, datastores, data flows, environments, external systems, a glossary and conventions. Agents ask where_is, get the context for the paths they touch, and check the impact of a change.

How facts are learned and corrected

  • A fact learned twice by different sessions gains a confirmation.
  • A fact that contradicts an earlier one is kept beside it, newest first, and flagged for a person.
  • Agents can correct and forget facts. coflow context stale lists facts that may be out of date.
  • promote writes one proposal for many facts. A person reviews it and accept moves them into the declared layer as verified.

Playbooks

Playbooks tell agents when to use another system (observability, cloud, issue tracker) and how, with read-only queries. coflow context setup runs detection, installs the playbooks whose systems exist and writes five questions for a person to answer once.

Credentials and the server

No context file stores a credential value, only a reference naming where it lives. On the hosted service, the detected layer is whatever coflow sync last posted, and a scheduled job flags learned facts that are unverified, unconfirmed and older than 90 days.
