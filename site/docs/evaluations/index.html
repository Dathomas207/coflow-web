Evaluations and harness

Measure a reviewer or a rule on a pinned dataset before you trust it with more autonomy.

The harness

The harness tests a rule on its examples, runs a regression suite, replays a task and checks release gates. Every run is saved as a record pinned to the dataset version, engine and settings it used, so two runs can be compared.

Datasets

Datasets are original and synthetic: the code belongs to an invented shop service, with no customer code, names or records. There is one dataset per review agent with 20 or more cases, plus a core review set, a security set, a lessons set and an adherence set. Cases include violations, clean changes that look risky, near misses a linter does not flag, defects only on deleted lines, files outside a rule’s scope and generated files. Secrets in cases are fake and shaped to be recognized as fake.

Running an evaluation

coflow eval run review-core
coflow eval run security-monitor --tools all

A run is compared with the committed baseline. The default tool set is ruff alone, so baselines stay comparable across machines; a baseline records the tool set it was taken with, and runs with another tool set are compared only with a matching baseline.

Reading the results honestly

Linters alone reach a minority of expected findings. In the core review set, the tools find 11 of 39 expected findings; in the security set they find no missing authorization, no missing tenant scope and no request forgery. Those findings need a model review.

Each agent template carries proposed precision and recall thresholds. They are starting values and have not been validated against a hosted model or real pull requests. Runs with linters alone do not meet them, so promotion above shadow needs a model-backed run.

Evaluations and promotion

Promoting an agent to assist or auto needs a regression run on the agent’s own dataset whose precision and recall meet its thresholds. A partial run, or a run on another dataset, is refused. See Agent Studio.

Adding cases

Add a case from a real incident by writing a sanitized, synthetic version of the change that caused it. Under the planned billing model, evaluations that call a model use credits.
