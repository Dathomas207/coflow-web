Feature availability

Implementation, configuration and live availability are different states.

Implemented in source

The guides cover rules and reviewed revisions, task compilation, package-linked outcomes, organization/project access, PostgreSQL RLS, Workflow Studio, specifications and acceptance contracts, knowledge search and source connection workflows.

This documentation was reviewed against source revision 6d7ba3d. Source implementation is not a claim that every workspace has been deployed or configured with it.

Configuration and rollout gates

Turning on single sign-on for a workspace requires verified membership, ownership backfill, policy coverage and a restricted runtime role. Workflow Studio, MCP catalogs, agent lifecycle/activity and source jobs have feature/configuration gates. Semantic retrieval/provider features have separate activation and budget requirements.

Boundaries to preserve

  • Agent lifecycle/activity records do not prove native provider discovery or execute coding agents.
  • Workflow replays and submitted acceptance reports are client-reported unless independently verified elsewhere.
  • MCP catalog approval does not connect a remote server.
  • Rule approval does not install RLS in another application.
  • Token budgets are not a published savings benchmark.

Confirm your workspace

Ask for the deployed version, enabled modules, sign-in URL and authorized projects during onboarding. Use account-specific application status and release evidence rather than marketing examples to decide what is live.
