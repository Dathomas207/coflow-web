Coding agents, MCP and source connections

Connect reviewed engineering context without assuming every adapter is enabled.

Local MCP

The checked-in CoFlow MCP server runs over stdio and delegates calls to the authenticated API. Core tools include compile_instructions, record_outcome, get_context, capture_memory and export_workspace. Approval remains a separate authorized API/UI workflow.

Use the installed python -m app.mcp_server entry point, your provisioned MEMORY_API_URL and an authorized MEMORY_API_TOKEN supplied through your local secure environment. Never paste credential values into repository configuration.

Agent instructions and exports

Approved workspace exports return AGENTS.md and MEMORY.md content without writing files on your machine. Review and place the exports in the workspace your agent reads. Local MCP compatibility depends on the client’s ability to launch a stdio server and use your approved configuration.

GitHub and Jira

The integration implementation includes organization-owned GitHub/Jira connection flows through Nango. GitHub capture uses an allowlisted repository and creates pending knowledge for review. Source-sync jobs require configured queues/workers and recheck authorization. Jira connection authorization does not imply issue synchronization is available.

MCP configuration catalog

The catalog versions, validates, reviews and audits MCP server descriptors. An approved descriptor starts disabled, and enablement requires a separate reviewed flag. Catalog records do not launch processes, connect to external servers or resolve secrets.

Availability limits

Do not use a sample hosted MCP URL as proof of a live CoFlow service. The stdio server in source is distinct from a remote HTTP/OAuth connector. Account provisioning, provider adapters and runtime flags must be verified for the release you use.
